Adding the GitHub Actions secrets

The workflow reads APIFY_API_TOKEN and NTFY_TOPIC from repo secrets — they're never written into any file that gets committed. Do this once, from a repo you've already pushed to GitHub.

  1. Open the repo's secrets page

    On GitHub: your repo → Settings → Secrets and variables → Actions → New repository secret.

  2. Add APIFY_API_TOKEN

    Name it exactly APIFY_API_TOKEN. Paste the value from your local .env — not from instructions.md, which you're about to delete.

    Name: APIFY_API_TOKEN Value: (from .env → APIFY_API_TOKEN=…)

  3. Add NTFY_TOPIC — optional

    The code already defaults to graham_katana_research_digest_986712 if this secret is absent, so only add it if you want the workflow to use a different topic than local.

    Name: NTFY_TOPIC Value: graham_katana_research_digest_986712

  4. Confirm the workflow can push back to the repo

    The workflow commits data/seen.json and digests/ after every run. It already requests this via permissions: contents: write in digest.yml — but if your org sets a stricter org-wide default, override it locally too:

    Settings → Actions → General → Workflow permissions → Read and write permissions.

  5. Run it once by hand

    Actions tab → Daily Research Digest → Run workflow. Watch it fetch, dedupe, write a digest, notify, and commit the updated state — before trusting the 07:30 SAST schedule to do it unattended.

  6. Now delete instructions.md

    Its only sensitive contents — the Apify token — already live in your gitignored .env and (after step 2) in the GitHub secret. Nothing else depends on the file.

Rotate the token anyway. It was pasted in plaintext into instructions.md and shared in this conversation, so treat it as exposed regardless of where it ends up — generate a fresh one in the Apify console and swap it into .env and the GitHub secret.
